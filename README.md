# Neko — умная колонка на ESP32 + ПК

«Нэко» — самодельная голосовая колонка. ESP32 собирает/проигрывает звук по I2S,
весь «мозг» (распознавание, LLM, синтез речи) живёт на ПК.

```
[INMP441] -> I2S -> ESP32 --TCP 192.168.0.200:4211--> ПК (VAD → Whisper → Qwen → Silero) --PCM--> ESP32 -> [MAX98357A] -> динамик
```

## Железо

| Компонент        | Модель       |
|------------------|--------------|
| Плата            | ESP32 DevKit V1 (GPIO-пины) |
| Спикер-усилитель | MAX98357A (I2S, класс D, 3.2 Вт / 4Ω) |
| Микрофон         | INMP441 (I2S MEMS) |
| Динамик          | 4–8Ω, до ~3 Вт |
| Блок питания     | USB 5В / 2А (см. «Питание» ниже) |

## Схема подключения

### Динамик-усилитель MAX98357A (`esp32_speaker/src/main.cpp:17`)
| Пин модуля      | Куда               | Комментарий |
|-----------------|--------------------|-------------|
| `BCLK`          | ESP32 **GPIO26**   | битклок |
| `LRC`           | ESP32 **GPIO25**   | word select / frame |
| `DIN`           | ESP32 **GPIO22**   | данные |
| `VIN`           | **5В** (общая шина) | питание усилителя |
| `GND`           | **GND**            | общий с ESP32 |
| `OUT+` / `OUT-` | динамик **+/−**    | без риска полярности, но держите порядок |

> Важно: класс-D с ВЧ-помехами — держите провода BCLK/LRC/DIN короткими, GND звездой.

### Микрофон INMP441 (`main.cpp:22`)
| Пин модуля | Куда              | Комментарий |
|------------|-------------------|-------------|
| `VDD`      | ESP32 **3.3V**    | **ТОЛЬКО 3.3В, не 5В!** |
| `GND`      | **GND**           | |
| `SCK`      | ESP32 **GPIO18**  | битклок |
| `WS`       | ESP32 **GPIO19**  | word select |
| `SD`       | ESP32 **GPIO34**  | данные (вход, только вход!) |
| `L/R`      | **GND**           | выбрает левый канал |

### Питание
- ESP32 и MAX98357A сидят на одной шине 5В, GND у всех общий («звездой»).
- **Баг этого DevKit**: через разъём USB-C до платы доходит ~4В вместо 5
  (высокое сопротивление в коннекторе/дорожках) — при этом ESP32 нестабилен.
  Питайте ESP32 через пин **VIN** напрямую от 5В/2А, разъём USB-C не используйте.
- INMP441 питается от 3.3В со стабилизатора ESP32 — это нормально.

## Прошивка (PlatformIO)

```bash
cd /mnt/hdd/neko/esp32_speaker

# собственно колонка (WiFi + TCP :4211, микрофон вверх, динамик вниз)
pio run -e esp32dev -t upload

# тест микрофона: уровни rmsL/rmsR на Serial
pio run -e mic_probe -t upload && pio device monitor -e mic_probe

# тест усилителя: 4 тона (440/1000/3000/100 Гц) по кругу, без WiFi
pio run -e amp_probe -t upload && pio device monitor -e amp_probe
```

Тест усилителя запускается **только после проверки модуля омметром**: на живой
плате между `OUT+`/`OUT-`/`GND` не должно быть единиц мОм (мёртвый мост = КЗ).

### Сеть (в `esp32_speaker/src/secrets.h`, шаблон — `secrets.h.example`)
```cpp
#define WIFI_SSID "YOUR-SSID"      // точка доступа
#define WIFI_PASSWORD "YOUR-PASS"  // пароль
#define OTA_PASSWORD "neko-ota"    // пароль OTA (совпадает с `-a` в ota.sh)
```
Статик-адрес колонки: `192.168.0.200` (его ждёт `assistant.py`), меняется там же.

### Прошивка по сети (OTA)
Боевая прошивка умеет обновляться по WiFi (ArduinoOTA, порт 3232). Пароль задаётся
в `esp32_speaker/src/secrets.h` (`OTA_PASSWORD`) и подхватывается `ota.sh` автоматически
(в самом репозитории пароля нет):

```bash
/mnt/hdd/neko/ota.sh     # = pio run -e esp32dev_ota -t upload на 192.168.0.200
```

Условия: колонка в сети и уже стоит OTA-прошивка. **Если WiFi недоступен** —
только UART (`pio run -e esp32dev -t upload`). Адрес меняется в
`platformio.ini` (`[env:esp32dev_ota]`).

### Прошивка без USB-C
Разъём сгоревший/дубеющий — через **Arduino Uno как USB-UART**:
- вынуть ATmega328 из панельки Uno;
- Uno `RX(0)` → ESP32 `TX0`, `TX(1)` → ESP32 `RX0` через делитель `1к + 2к` (3.3В-уровень);
- общий GND, `IO0→GND` + коротко `EN→GND` — вход в режим загрузки вручную;
- `pio run -e esp32dev -t upload`.
В сервисном случае оставьте с ESP32 доступными: `TX0 RX0 GND IO0 EN`.

## ПК-часть

```bash
cd /mnt/hdd/neko
./run.sh
```

`run.sh` запускает `assistant.py` в venv с логами (`-u`). Модели грузятся ~20–30 с.
Если рядом лежит `ha_env.sh` (токен HA), он подхватывается автоматически — колонка получает
доступ к управлению домом.

### Home Assistant (необязательно)
`neko_ha.py` ходит в HA по REST (URL и long-lived токен берёт из env `HA_URL`/`HA_TOKEN`
или из `ha_env.sh`, который `run.sh` подключает при старте).

`assistant.py` отдаёт Qwen 2.5 7B инструменты (`ha_*`) через OpenAI function calling в LM Studio:
- `ha_get_state(entity_id)` — состояние сущности (погода, заряд, свет…);
- `ha_find_entity(фрагмент)` — поиск сущности по имени («виталя»);
- `ha_call_service(domain, service, entity_id, data)` — управление (свет, пылесос, список покупок);
- `ha_list_entities()` — список доступных сущностей.

Известные сущности дома (зашиты в системный промпт): `weather.forecast_home`, `sun.sun`,
`vacuum.koridor_vitalia` (+ `select.koridor_vitalia_uborka`, заряд), `todo.shopping_list`.
Проверка данных/путь управления тестировался на этих объектах; свет/очиститель/аэрогриль
добавляются в HA из miot — они подтянутся через `ha_find_entity` автоматически.

> Управление идёт по REST-маршрутизации: LLM сам выбирает entity и сервис,
> Python исполняет и возвращает результат в диалог. Данные HA не выдумываются — только что вернул API.

### Музыка (Яндекс Музыка)
«Нэко, включи музыку» / «поставь песню <название>» / «стоп» обрабатываются без LLM —
`neko_music.py` ищет трек через yandex-music (OAuth device flow), спускает его
`ffmpeg → s16le 48к моно` и стримит в то же TCP-соединение на ESP32.

Токен (разово):
```bash
venv/bin/python ym_token.py   # откроешь ya.ru/device, введёшь код — токен сам впишется
```
в `music_env.sh` (`YANDEX_MUSIC_TOKEN`, chmod 600), `run.sh` подхватывает при старте.
Без токена можно так же играть любую прямую ссылку (`neko_music.py <URL>`).

> Во время воспроизведения микрофон ESP32 ставится на паузу (чтобы колонка не слышала себя),
> поэтому «стоп» сработает после конца трека. Уровень динамика — `VOLUME` в `main.cpp`.

### Кнопки (ESP32)
Три кнопки на GPIO, подтяжка к GND (внутренний `INPUT_PULLUP`):

| Кнопка    | GPIO | Что делает |
|-----------|------|------------|
| `VOL+`    | 27   | громкость вверх (0..10, шаг 1) |
| `VOL-`    | 4    | громкость вниз |
| `MAIN`    | 33   | см. ниже |

Кнопка `MAIN` — контекстная, решение принимает ПК (пауза/стоп музыки — только он знает, что играет):
- 1 клик, колонка молчит → включить/выключить микрофон (голосовой ответ «микрофон включён/выключен»);
- 1 клик, колонка говорит → стоп речи;
- музыка играет: 1 клик = пауза/продолжить, длинное (0.8с) нажатие = стоп.

Управляющий TCP-канал: `:4212` (строки через `\n`). Ходят `EV BTN SHORT/LONG 0/1`,
`EV MUTE 0|1`, `EV VOL` (ESP32→ПК) и `FLUSH`, `MUTE 0|1`, `VOL n` (ПК→ESP32).
`FLUSH` сбрасывает буфер динамика — используется при стопе речи/музыки, паузе.

### Авторизация TCP-каналов
Оба порта (`:4211` и `:4212`) требуют токен: сразу после подключения клиент шлёт
`AUTH <токен>\n`, в ответ сервер отвечает `AUTH OK`, иначе закрывает соединение.
Токен задаётся в `esp32_speaker/src/secrets.h` (`AUTH_TOKEN`), это один общий секрет
для прошивки и ПК. Если при этом у вас нет токена в `secrets.h`, клиенты (assistant.py,
neko_music.py, mic_debug.py, mic_preview.py) читают его из того же файла автоматически.
Токен можно переопределить через env `NEKO_AUTH_TOKEN`.

### Флоу работы
1. Тишина: колонка в режиме idle (`[VAD] жду wake-word «Neko»...`) и слушает микрофон.
2. Слышит «Нэко»/«неко» и т.п. (нечёткое совпадение, `WAKE_RATIO=0.72`) → чима («туньдунь»).
3. Команда той же фразой → сразу ответ. Чистая «Neko» → режим команды на `MAX_LISTEN_S` (5 с).
4. Фраза → VAD (тишина 600мс) → Whisper small (RU) → Qwen 2.5 7B (LM Studio, порт 1234) → Silero `v5_5_ru/kseniya` (48к) → PCM по TCP на ESP32.
5. Если за окно никто не заговорил — `[CLEAR]`, обратно в idle. Цифры TTS переписываются словами (`num2words`).

> Требуется запущенный LLM-сервер OpenAI-совместимого формата (по умолчанию
> `http://localhost:1234/v1/chat/completions`, модель `qwen2.5-7b-instruct`)
> (например, LM Studio с включённым локальным сервером).

## Настройка (env-переменные)

| Переменная       | По умолчанию         | Что делает |
|------------------|----------------------|------------|
| `ESP32_HOST`     | `192.168.0.200`      | адрес колонки |
| `ESP32_PORT`     | `4211`               | TCP-порт |
| `USE_WAKE_WORD`  | `1`                  | `0` — убрать wake-word, слушать всегда |
| `WAKE_WORDS`     | `неко,нэко,neko`     | список через запятую |
| `WAKE_RATIO`     | `0.72`               | порог нечёткого матча (0..1) |
| `LLM_URL`        | `http://localhost:1234/v1/chat/completions` | endpoint LLM |
| `LLM_MODEL`      | `qwen2.5-7b-instruct`| имя модели |
| `CHIME_FILE`     | `chime.wav`          | файл чимы (16/48к, любой, нормализуется до пика 0.9) |
| `CHIME_SLEEP`    | `0.4`                | пауза после чимы, с (эхо динамика) |
| `MAX_LISTEN_S`   | `5`                  | окно ожидания команды после чимы |
| `YANDEX_MUSIC_TOKEN` | —                  | токен Яндекс Музыки (из `music_env.sh`) |
| `ESP32_CTRL_PORT` | `4212`               | TCP-порт управляющего канала (кнопки) |

Пример:
```bash
USE_WAKE_WORD=1 WAKE_RATIO=0.75 MAX_LISTEN_S=7 ./run.sh
```

## Превью микрофона

```bash
/mnt/hdd/neko/venv/bin/python /mnt/hdd/neko/mic_preview.py
```
Qt6-окно: осциллограмма, dBFS-метр (маркер −30дБ «ГОВОРИТ»), выбор входа/выхода
(авто-выбор fifine/pulse), запись в `mic_record.wav`, кнопка «Слушать» (прямой
проброс микрофона в наушники/колонку ПК).

> Колонка принимает **одно** TCP-соединение. `run.sh` и `mic_preview.py`
> одновременно не работают.

## Диагностика

| Симптом | Что делать |
|---------|------------|
| Колонка молчит | `amp_probe` (тоны). Замер омметром выхода модуля перед включением. |
| Тоны есть, речи нет | `mic_probe` — прыгают ли `rmsL/rmsR` при разговоре. |
| ESP32 нестабилен / 4В на 5В шине | дефект USB-кабеля (было) — попробовать другой кабель, питание через `VIN`. |
| Wake-word не ловится | ослабить `WAKE_RATIO` (0.65), проверить уровень микрофона в `mic_preview`. |
| Музыка не играет | `network` токен Я.Музыки: `venv/bin/python ym_token.py`; проверить `echo $YANDEX_MUSIC_TOKEN`. |
